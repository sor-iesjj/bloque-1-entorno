> [!abstract] Para qué sirve esta hoja
> - **Vale para las dos ediciones:** [B1.14a Cole](B1_14.a_Ubuntu_Server_y_SSH_desde_Windows_Fisico_Cole.md) y [B1.14a Casa](B1_14.a_Ubuntu_Server_y_SSH_desde_Windows_Fisico_Casa.md). Los comandos de Ubuntu son exactamente los mismos.
> - **Solo están los que se escriben en Ubuntu Server**, en el orden en que aparecen en la práctica. Los de PowerShell de Windows están en la propia práctica.
> - **Por qué existe:** en la consola de la VM no puedes copiar y pegar. Tienes que teclearlos, así que aquí los tienes uno a uno, con lo que hace cada trozo.

> [!tip] Tres trucos para teclear menos y equivocarte menos
> - **Tecla `Tab`:** escribe el principio de un comando o de una ruta (`/etc/net`) y pulsa `Tab`: Linux completa el resto. Si no completa, es que lo que llevas escrito está mal.
> - **Flecha arriba `↑`:** recupera los comandos que ya escribiste. `ip -br a` lo vas a usar cinco veces: no lo escribas cinco veces.
> - **La contraseña de `sudo` no se ve** mientras la escribes. No aparecen ni asteriscos. Escríbela y pulsa `Intro`.

> [!warning] El fallo nº1: escribir un comando de Ubuntu en PowerShell (o al revés)
> Todo lo de esta hoja se escribe **en Ubuntu**: en la consola de la VM o, a partir del comando 18, también dentro de la sesión SSH. Si el *prompt* empieza por `PS C:\…>`, estás en Windows. Si es del tipo `tu_usuario@servidor:~$`, estás en Ubuntu.

---

### Comando 1 · ⌨️ Cambiar el teclado a español

```bash
sudo dpkg-reconfigure keyboard-configuration
```

- **Cuándo:** la primera vez que entras en Ubuntu Server, **antes que nada**. Si la instalación desatendida no se desactivó bien, Ubuntu se queda con el teclado **inglés (UK)** y las teclas no escriben lo que pone en ellas.
- **Qué hace:** abre un asistente **en modo texto** para volver a configurar el teclado.
  - `sudo` → ejecuta el comando como administrador.
  - `dpkg-reconfigure` → vuelve a lanzar las preguntas de configuración de un paquete ya instalado.
  - `keyboard-configuration` → el paquete que guarda la configuración del teclado.
- **Qué eliges en el asistente** (te mueves con las flechas, `Intro` para aceptar):
  1. Modelo de teclado → **Generic 105-key PC** (PC genérico de 105 teclas).
  2. País de origen → **Spanish**.
  3. Distribución → **Spanish**.
  4. Tecla AltGr → la que viene por defecto (*The default for the keyboard layout*).
  5. Tecla Compose → **No compose key**.
- **Truco para escribir el guion con el teclado UK:** las letras están en su sitio, pero el **guion `-` no**. Con el teclado mal puesto, el guion sale pulsando la tecla **`'`** (la que está a la derecha del `0`).

### Comando 2 · ✅ Aplicar el teclado nuevo sin reiniciar

```bash
sudo setupcon
```

- **Qué hace:** carga en la consola la configuración de teclado que acabas de elegir.
- **Compruébalo:** escribe `ñ` y un guion `-`. Si salen bien, ya está. Si no, reinicia con `sudo reboot` (comando 23) y vuelve a probar.

### Comando 3 · 🔌 Apagar el servidor

```bash
sudo poweroff
```

- **Qué hace:** apaga Ubuntu de forma ordenada, cerrando los programas y el disco antes de cortar.
- **Cuándo:** Paso 2.b (antes de la instantánea y la exportación en Cole), Paso 6 (antes de tocar la red en VirtualBox) y Paso 10 (al terminar).
- Espera a que VirtualBox muestre la VM **Apagada** antes de cambiar nada. Si lo escribes dentro de SSH, la conexión se corta: es normal.

### Comando 4 · 🌐 Ver las tarjetas de red y sus IP

```bash
ip -br a
```

- **Qué hace:** lista las tarjetas de red con su estado y su dirección IP, una por línea.
  - `ip` → la herramienta de red de Linux.
  - `-br` → *brief*, salida resumida.
  - `a` → *address*, las direcciones.
- **Qué esperas ver:** una tarjeta con `10.0.2.15` (la del NAT) y otra **sin IPv4** (la de `LAB_RED`). Después del Paso 4, esa segunda debe salir **UP** con `10.10.10.10/24`.
- **Cuándo:** Pasos 3, 4, 8 y 9.

### Comando 5 · 🏷️ Ver la MAC de cada tarjeta

```bash
ip link
```

- **Qué hace:** muestra las tarjetas con su dirección física (MAC), en la línea `link/ether`.
- **Para qué:** comparar la MAC de la tarjeta sin IP con la que apuntaste en VirtualBox. VirtualBox la escribe seguida (`080027…`) y Linux con dos puntos (`08:00:27:…`). La que coincide es la tuya; normalmente se llama `enp0s8`.

### Comando 6 · 📂 Ver qué ficheros de red hay

```bash
ls /etc/netplan/
```

- **Qué hace:** lista (`ls`) el contenido de la carpeta `/etc/netplan/`, donde Ubuntu guarda la configuración de red.
- **Qué esperas ver:** el fichero que dejó el instalador, por ejemplo `00-installer-config.yaml` o `50-cloud-init.yaml`.

### Comando 7 · 👀 Leer la configuración que dejó el instalador

```bash
sudo cat /etc/netplan/*.yaml
```

- **Qué hace:** muestra en pantalla el contenido de los ficheros de red.
  - `cat` → enseña el contenido de un fichero.
  - `*.yaml` → el asterisco significa «todos los que acaben en `.yaml`», así no tienes que escribir el nombre.
- **Fíjate** en si tu tarjeta del laboratorio aparece con `dhcp4: true`.

### Comando 8 · ✏️ Crear el fichero de la IP fija con nano

```bash
sudo nano /etc/netplan/60-laboratorio.yaml
```

- **Qué hace:** abre el editor de texto `nano` sobre un fichero **nuevo** llamado `60-laboratorio.yaml`. Si no existe, lo crea al guardar.
- **Lo que escribes dentro**, con **espacios, nunca tabuladores** (cada nivel son dos espacios):

```yaml
network:
  version: 2
  ethernets:
    enp0s8:
      dhcp4: false
      addresses:
        - 10.10.10.10/24
```

- Si tu tarjeta no se llama `enp0s8`, pon **tu** nombre (el que viste con el comando 5).
- **Teclas de nano:**
  - `Ctrl + O` y luego `Intro` → guardar.
  - `Ctrl + X` → salir.

### Comando 9 · 🔒 Proteger el fichero de red

```bash
sudo chmod 600 /etc/netplan/60-laboratorio.yaml
```

- **Qué hace:** cambia los permisos (`chmod`) para que **solo `root`** pueda leer y escribir el fichero (`600`).
- **Por qué:** netplan lo recomienda, porque estos ficheros a veces guardan contraseñas de wifi. Si no lo haces, te sale un aviso cada vez.

### Comando 10 · 🧪 Probar la IP fija con red de seguridad

```bash
sudo netplan try
```

- **Qué hace:** aplica la nueva configuración de red **de prueba** y te pide que pulses `Intro` para confirmarla.
- **La red de seguridad:** si en **120 segundos** no pulsas `Intro`, lo deshace solo. Por eso se usa `try` y no `apply`.
- Si da error, casi siempre es el YAML: un tabulador, un espacio de menos o el nombre de la tarjeta mal escrito. Vuelve al comando 8.
- Después, comprueba con `ip -br a` (comando 4).

### Comando 11 · 🔄 Actualizar la lista de paquetes

```bash
sudo apt update
```

- **Qué hace:** descarga de Internet el **catálogo** actualizado de programas disponibles.
- **Lo que NO hace:** no actualiza ningún programa. Solo refresca la lista.
- **Cuándo:** Paso 5 (antes de instalar) y Paso 9 (para comprobar que hay Internet tras reiniciar). Tiene que terminar sin errores.

### Comando 12 · 📦 Instalar el servidor SSH

```bash
sudo apt install openssh-server
```

- **Qué hace:** instala el programa que acepta conexiones SSH, con todo lo que necesita. Si ya estaba instalado, te lo dice y no hace nada.
- Si pregunta `¿Desea continuar? [S/n]` (o `[Y/n]`), pulsa `Intro`.

### Comando 13 · 🩺 Comprobar que la configuración de SSH no tiene errores

```bash
sudo sshd -t
```

- **Qué hace:** revisa (`-t`, *test*) la configuración del servidor SSH y sus claves.
- **Resultado bueno:** **no sale nada**. En Linux, el silencio significa «todo bien».

### Comando 14 · 📋 Ver la configuración real de SSH

```bash
sudo sshd -T
```

- **Qué hace:** con la `T` **mayúscula**, muestra todos los ajustes que SSH está usando de verdad.
- **Busca** estas tres líneas: `port 22`, `passwordauthentication yes` y `hostkey /etc/ssh/ssh_host_ed25519_key`.
- Ojo: `-t` (minúscula) y `-T` (mayúscula) son **dos comandos distintos**.

### Comando 15 · 👂 Ver qué puertos están escuchando

```bash
sudo ss -ltnp
```

- **Qué hace:** lista las «puertas abiertas» del servidor.
  - `-l` → solo las que están escuchando.
  - `-t` → solo TCP.
  - `-n` → números de puerto, sin traducirlos a nombres.
  - `-p` → qué programa hay detrás.
- **Qué esperas ver:** el puerto **`22`** escuchando (en `0.0.0.0:22` o `*:22`), con `sshd` o `systemd` detrás.

### Comando 16 · 🧱 Consultar el cortafuegos

```bash
sudo ufw status
```

- **Qué hace:** dice si el cortafuegos de Ubuntu (`ufw`) está activo o no.
- Si pone **inactive**, déjalo así. Si está **active**, **no lo desactives**: avisa al profesor.

### Comando 17 · ▶️ Arrancar el servicio SSH (solo si hace falta)

```bash
sudo systemctl start ssh.service
```

- **Cuándo:** **solo** si el comando 15 no enseña el puerto `22`.
- **Qué hace:** pide al gestor de servicios de Ubuntu (`systemctl`) que arranque (`start`) el servidor SSH ahora mismo.
- Después repite el comando 15 y busca el `22`.

### Comando 18 · 🔑 Ver la huella del servidor

```bash
sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

- **Qué hace:** muestra la «huella dactilar» de la clave pública del servidor.
  - `ssh-keygen` → la herramienta de claves de SSH.
  - `-l` → enseña la huella.
  - `-f` → del fichero que va a continuación.
- **Para qué:** anota la cadena que empieza por `SHA256:` y comprueba que pone `ED25519`. Cuando conectes desde Windows, el cliente te enseñará una huella: **solo aceptas si es la misma**.
- Usa `Tab` para la ruta: es la más larga de toda la práctica.

> [!info] A partir de aquí ya puedes estar dentro de SSH
> Los comandos 19 a 22 los escribes en la sesión SSH abierta desde PowerShell. Ahí **sí** puedes copiar y pegar, pero escríbelos igual: así se te quedan.

### Comando 19 · 👤 ¿Quién soy?

```bash
whoami
```

- **Qué hace:** muestra el usuario con el que has entrado. Debe ser tu usuario de Ubuntu.

### Comando 20 · 🖥️ ¿En qué equipo estoy?

```bash
hostname
```

- **Qué hace:** muestra el nombre del equipo. Dentro de SSH debe salir el nombre del **servidor Ubuntu**. Después de `exit`, el mismo comando en PowerShell te dará el nombre de tu **Windows**: esa diferencia es la prueba.

### Comando 21 · 📍 ¿En qué carpeta estoy?

```bash
pwd
```

- **Qué hace:** muestra la carpeta actual (*print working directory*). Debe salir algo como `/home/tu_usuario`: una ruta de Linux, no de Windows.

### Comando 22 · 🚪 Salir de la sesión SSH

```bash
exit
```

- **Qué hace:** cierra la sesión remota. La ventana vuelve a ser PowerShell de Windows.
- **No apaga** el servidor: solo te desconecta de él.

### Comando 23 · 🔁 Reiniciar el servidor

```bash
sudo reboot
```

- **Qué hace:** reinicia Ubuntu.
- **Para qué (Paso 9):** demostrar que todo **sobrevive al reinicio**. Después vuelves a entrar por SSH y repites `ip -br a` (comando 4) y `sudo apt update` (comando 11).
